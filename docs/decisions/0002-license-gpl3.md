# ADR 0002：采用 GPL-3.0 作为项目许可

- **状态**：已采纳
- **日期**：2026-10-06
- **相关**：[README「许可」](../../README.md)、`LICENSE`

## 背景

仓库初始化时附带了 GNU **GPL-3.0** 的 `LICENSE` 全文。需要确认这是有意的选择，并明确它与产品路线的相互作用：

- 产品形态是**以服务形式对外提供**，不是分发软件副本；
- 未来要**接入公司内部经营数据**（ERP），可预见的形态仍以自用与服务为主。

## 决策

采用 **GPL-3.0**，保留仓库中的 LICENSE 原文；不以其他许可替代。

## 理由

1. **服务形式不构成"分发"。** GPLv3 **没有**网络服务条款（那是 AGPLv3 才有的）——以 SaaS / 服务形式提供使用，不触发"提供对应源码"的义务。因此 copyleft 与商业模式不冲突。
2. **软件本体的开源不损害价值。** 本项目的价值在**数据、领域资产（本体 / 词典 / 映射 / 评分卡）与运营**，不在代码本身；代码开源反而利于方法论沉淀与协作。
3. **与"沉淀可复用方法论"的路线一致。** copyleft 保证衍生作品回馈，符合"希望这套方法论可被复用与检验"的取向。

## 后果

**正面**
- 可自由使用 GPLv3 兼容的第三方组件与开源数据集。
- 领域资产（`domains/ivd/`）与内核可对外公开，不妨碍以服务形式运营。

**代价与需注意（诚实记录）**
- **一旦分发软件本体**（客户私有化部署、发布二进制、交付源码），必须以 GPL-3.0 提供**完整对应源码**。
- **引入依赖前必须核对其许可兼容性**：与 GPLv3 不兼容的许可（部分专有 SDK、商业许可的数据库驱动等）不得引入。当前已计划用到的 SQLite（public domain）、PostgreSQL（PostgreSQL License）、Neo4j（GPLv3 / 商业双许可）需在真正引入时逐项核对。
- 当前许可**不提供**"服务形式也须开源"的保护——若将来需要该保护，须改用 AGPL-3.0（属新决策）。
- 若将来要改为闭源分发，需重新评估（新开 ADR，并在本篇标注被替代）。

## 被否决的替代方案

| 方案 | 为什么没选 |
|---|---|
| MIT / Apache-2.0 | 允许闭源再发布，与"沉淀方法论并回馈"的取向不符 |
| **AGPL-3.0** | 服务形式亦触发源码义务，对本项目约束过强 |
| 不加许可（保留全部权利） | 无法合规使用多数开源组件，也不利于协作 |
| 专有 / 商业许可 | 与"方法论可复用、可对外讲"的路线冲突 |
